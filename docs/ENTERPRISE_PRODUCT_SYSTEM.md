# 企业级后台产品规范

这份文档是 `DESIGN.md` 的业务落地层。`DESIGN.md` 规定视觉和组件语言，
本文件规定业务页面如何组织任务、数据、权限和反馈。

## 1. 先定义任务，再选择页面

每个页面开始前必须写清楚以下五项：

| 项目 | 必答问题 |
| --- | --- |
| 主要岗位 | 谁每天使用这个页面？ |
| 主要任务 | 用户进入页面后要完成什么？ |
| 判断依据 | 用户需要比较哪些字段或状态？ |
| 主操作 | 页面最重要的下一步是什么？ |
| 失败恢复 | 失败后用户如何继续，不丢什么上下文？ |

一个页面只能有一个主要任务。其他信息必须服务于这个任务，不能因为
“以后可能有用”而全部放到首屏。

## 2. 页面类型决策表

| 用户任务 | 页面模式 | 首屏必须有 | 不要放在首屏 |
| --- | --- | --- | --- |
| 找到并处理一批记录 | `ListPage` / `PagePattern list` | 状态筛选、搜索、关键字段、行操作 | 审计全文、技术 ID |
| 创建或修改一条记录 | `CreatePage` / `EditPage` / `PagePattern form` | 字段分组、校验、保存状态 | 无关统计、重复说明 |
| 查看一条记录并追溯原因 | `ShowPage` / `PagePattern detail` | 摘要、状态、主操作、最近变更 | 全部关联表 |
| 连续处理一个对象的多个阶段 | `WorkspaceLayout` / `PagePattern workspace` | 对象列表、当前对象、阶段动作 | 过多导航和重复标题 |
| 观察趋势并进入处理 | `DashboardPage` | 业务指标、异常、钻取入口 | 只有装饰没有动作的图表 |

资源 CRUD 优先使用 `ListPage`、`CreatePage`、`EditPage`、`ShowPage`。
只有自定义业务编排才使用 `PagePattern`。`PagePattern` 只负责布局和状态
呈现，不负责查询、权限、提交和业务决策。

## 3. 列表页标准工作流

列表页按以下顺序组织：

```text
页面标题 + 主操作
状态视图（可选）
搜索 / 筛选 / 保存视图
批量操作（仅在有选择时出现）
表格或列表
分页 / 总数 / 数据新鲜度
```

### 字段与操作规则

- 首屏优先展示：业务标识、当前状态、负责人或截止时间、下一步动作。
- 字段必须能帮助用户排序、筛选或做决定；不能只因为数据库里存在就展示。
- 行内只保留最高频动作，其他动作进入 `...` 菜单。
- 危险操作必须显示影响范围，并在确认完成前保持原页面上下文。
- 批量操作只对当前选择生效；跨页选择必须明确提示选择范围。
- 状态不能只靠颜色表达，必须同时有文字或图标。

### 列表状态矩阵

| 状态 | 页面内容 | 用户下一步 |
| --- | --- | --- |
| 初始加载 | 骨架或稳定占位，不跳动主操作 | 等待 |
| 初始为空 | 解释为什么为空 + 创建或导入入口 | 创建 / 导入 |
| 筛选无结果 | 当前筛选条件 + 清除筛选 | 清除 / 修改筛选 |
| 加载失败 | 失败原因范围 + 重试 | 重试或离开 |
| 无权限 | 权限边界 + 联系人或返回入口 | 返回 / 申请权限 |
| 有数据 | 表格、筛选、分页、行操作 | 处理记录 |
| 批量选择 | 选择范围、可用批量动作、清除选择 | 执行或取消 |

## 4. 反馈与状态归属

一个事件只能有一个主要反馈面：

| 事件 | 主要反馈 | 规则 |
| --- | --- | --- |
| 字段校验失败 | 字段下方错误 | 保留用户输入 |
| 普通保存成功 | Toast | 不再额外显示成功横幅 |
| 保存后进入完成态 | 页面状态 | 不重复发成功 Toast |
| 查询失败 | `DataState` / 错误反馈 | 不展示旧数据为当前数据 |
| 权限不足 | Forbidden 状态 | 不通过隐藏文案伪装成空数据 |
| 可撤销操作 | Undo Toast | 在撤销窗口内保持可恢复 |

页面组件拥有布局，业务组件拥有查询、权限、提交和数据状态。任何组件
都不得默认授予权限，也不得把演示数据或本地状态描述为已持久化。

## 5. 页面验收门槛

业务页面合入前必须完成：

1. 有一个明确的主要任务和一个主要操作。
2. 已选择正确的页面模式，没有重复标题或重复页面壳。
3. 已验证有数据、初始空、筛选无结果、加载、错误和无权限状态。
4. 已验证长标题、长字段、窄容器不会遮挡操作或产生不可解释的横向滚动。
5. 已验证键盘焦点、按钮名称、表单标签和状态文本。
6. 已验证成功、失败、权限和批量操作反馈各只有一个主要反馈面。
7. 真实业务页面使用真实权限和数据状态；Storybook 仅证明组合和交互样板。

实现时，筛选后的零结果必须使用 `filtered-empty`，不能复用初始
`empty`。否则用户会误以为系统没有数据，而不是当前条件没有匹配项。

## 6. 参考来源与使用边界

参考资料只借鉴“解决什么问题”，不复制外观：

| 参考 | 借鉴内容 | 不引入 |
| --- | --- | --- |
| Refine | 资源 CRUD、路由和数据状态 | 它的页面皮肤 |
| Ant Design | 表单校验、反馈、数据密集型场景 | 默认蓝色和组件装饰 |
| shadcn/ui | 组合方式、语义 token、可读源码 | 无约束的页面自由拼装 |
| Carbon / PatternFly | 企业通知、权限、空错误状态 | 厚重的品牌视觉 |
| Metronic / Fuse / Midone | 页面覆盖范围和信息架构 | 模板式卡片、渐变和营销布局 |

SVAdmin 自己的 token、无障碍契约、权限边界和页面模式优先级最高。

## 8. 工作台、审批和审计

### 工作台

工作台用于连续处理同一个对象的多个阶段，不是把多个页面简单并排。
标准区域为：

```text
WorkspaceLayout
├── summary（当前对象或阶段摘要）
├── primary（主要处理区）
└── secondary（检查器、审计或辅助信息）
```

`primary` 拥有当前任务和主操作，`secondary` 只能补充判断依据或追溯信息。
当对象切换时，主区域和检查器必须同步更新；不能保留上一个对象的审计或
操作按钮。

为工作台提供 `label`，让整个区域具备可识别的 landmark；使用
`mobileOrder` 表达窄屏下的任务优先级，不要通过 CSS 顺序偷偷改变操作顺序。

### 审批

审批页必须同时表达：

- 当前队列：待办或历史；
- 当前记录：申请人、状态、附件和版本；
- 允许的动作：由服务端返回，不由前端猜测；
- 动作结果：成功、版本冲突、契约错误或网络失败。

审批动作必须携带当前版本和幂等键。版本冲突时保留当前记录上下文，
不能把冲突误报为成功。

### 审计

审计时间线是详情页的补充内容，不替代主记录字段。主记录处于 loading、
forbidden 或 error 时，不显示旧的审计事件。空审计必须明确表示“暂无事件”，
不能伪装成加载失败或记录不存在。

这些流程分别使用 `WorkspaceLayout`、`ApprovalCenter` 和 `AuditTimeline`，
并通过以下契约标识进行验收：

```text
data-svadmin-workspace-layout
data-svadmin-approval-center
data-svadmin-approval-state
data-svadmin-audit-timeline
data-svadmin-audit-state
```
