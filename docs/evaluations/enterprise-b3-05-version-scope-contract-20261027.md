## 用户决策

1. **保留宿主差异展示**：SVAdmin 继续展示业务宿主提供的 `oldValue/newValue`
   差异数据，现有 `VersionDiffViewer` 及详情工作台 versions section 的展示契约保留。
2. **版本列表由宿主负责**：历史版本列表的数据来源、分页、排序、筛选、加载和错误
   呈现由业务宿主实现，不在 SVAdmin 内提供默认版本列表服务或版本列表 UI。
3. **版本选择由宿主负责**：选择某个历史版本、维护选中态、把选中版本映射为
   `oldValue/newValue` 的职责属于业务宿主；SVAdmin 不新增“选中记录版本”的公共 API
   或内部选择状态。
4. **版本恢复由宿主负责**：恢复、回滚、冲突处理、确认交互、权限校验和恢复后的
   数据刷新由业务宿主负责；SVAdmin 不提供恢复动作、恢复 Provider 或恢复 UI。
5. **SVAdmin 不提供版本服务**：不新增 `listVersions`、`getVersion`、`restoreVersion`
   或等价版本服务；不新增默认版本 Provider、版本 schema、版本权限协议或版本持久化。

## 验收边界

- 本轮只确认“范围选择”，不新增实现，也不把范围决策写成功能已实现。
- 保留范围：`VersionDiffViewer` 对宿主传入 `oldValue/newValue` 的静态差异展示、
  既有可访问性处理（模式按钮 `aria-pressed`、装饰图标 `aria-hidden`）和现有详情
  工作台 versions section 挂载契约。
- 明确移出 SVAdmin 范围：版本历史数据服务、版本列表、版本选择、版本恢复、版本级
  空态/错误/权限/冲突语义的默认实现。若未来业务宿主需要这些能力，应由宿主在其
  自身服务与权限边界内实现，或另立带明确产品/后端契约的任务。
- 不新增或重复：默认版本 schema、版本 Provider、版本选择状态、恢复 API、恢复 UI，
  以及仅用于证明上述不存在能力的本地测试或受控 case。
- 历史证据保留：验收矩阵与收口记录中既有版本差异静态渲染、详情工作台五区、
  受控浏览器和 RBAC 边界记录继续作为历史证据，不因本决策合并计数或外推为真实服务。

## 仍需外部输入的限制

  未验收；本决策不提供也不验证这些服务。
- **真实 RBAC/租户/字段授权**：版本查看、选择或恢复的真实权限、租户隔离、字段级
  授权和撤权时序未验收；SVAdmin 不新增版本权限协议。
