# 所有 Example 的 PM / UX 核查

日期：2026-09-21。本文保留整改前的只读审计快照；后续实施及验收以 [整改执行记录](remediation.md) 为准，不将下述旧发现当作当前未修复清单。

## 范围与方法

按 `pm-spec` 的 JTBD、信息降噪、渐进披露、操作闭环、加载/空/错误恢复四步核查。目标是让示例成为可理解、可操作、可复用的业务参考，不只是组件陈列。优先检查任务与结果是否可信，再处理布局和视觉一致性。

本轮只读业务代码，只新增核查文档。未恢复 Panda，未改动现有迁移成果，未提交、发布或部署。Metronic 的视觉方向作为既定背景，本轮不声称完成与线上参考站的逐像素比对。

562 是规范路由、query 视图和代表记录组合，不是 562 个独立页面模板，也不覆盖所有记录 ID、权限身份与无限参数组合。CRUD 别名与部分 settings 旧别名仅做源码映射，见分报告。共 153 个非 CRUD/代表视图另作联系表人工视觉检查；未声称逐张放大人工检查所有 CRUD 截图。

脚手架、验证 fixtures、未挂载页面、Example/Demo 命名组件已完成入口分类和源码核查，没有冒充已运行的应用。未实例化脚手架连接外部服务，也未扩展审计到 vendor 上游站点。

证据等级：

- 浏览器：路由加载、首屏与手机截图、DOM 信息、pageerror、document 溢出；2FA 另有定向操作复现。
- 源码确认：事件处理、数据来源、错误处理和状态流；分报告给出文件及行号。
- 待验证：故障注入、所有 POST、外部服务、完整权限组合和离开保护等未运行场景。不能从 HTTP 200 推导这些场景通过。

## 产品与视觉整改顺序

1. **先可信**：没有真实持久化或完整模拟闭环的动作，明确演示语义或禁用；不得报假成功。修复安全、导入、保存、状态门禁与指标口径。
2. **再可完成**：恢复核心创建、详情、筛选与推进操作；失败可重试且保留输入；补齐 Lite 开发入口。
3. **再可扫描**：每个业务区域突出对象、状态、下一步；减少重复指标、辅助摘要和多层框。Todo 优先保证任务列宽，窄屏收起辅助区域；日历保留移动端切月。
4. **最后统一**：以现有 Tailwind、语义 tokens、组件契约统一间距、控件密度、表格和标题。组件缺陷在库内修，页面特有布局在页面修，不以全局 CSS 掩盖行为缺陷。

Lite 的目标仍是原生链接/表单的 SSR 使用体验，不要求为了视觉完全一致引入 SPA 交互依赖。

## 五条跨范围验收场景

```gherkin
Scenario: 演示操作不冒充真实完成
  Given 页面未连接持久化或认证 Provider
  When 用户尝试保存、导入或启用二次验证
  Then 页面明确告知演示边界或禁用操作
  And 不显示已持久化、已导入真实成员或已启用真实安全能力

Scenario: 任务筛选与窄屏布局可信
  Given 同时存在未完成和已完成任务
  When 用户选择已完成视图并分别使用桌面和手机查看
  Then 所有任务列仅显示符合条件的记录
  And 标题和操作不互相遮挡
  And 新建与状态推进产生可核对的结果

Scenario: 日历星期与移动端切月正确
  Given 当前月份为 2026 年 7 月
  When 用户在手机上打开日历并切换月份
  Then 7 月 1 日位于星期三
  And 上月和下月操作始终可达

Scenario: Lite 提交失败保留输入
  Given 用户修改记录且服务端返回校验或保存失败
  When 页面收到失败响应
  Then 显示持续可见的失败原因
  And 保留用户刚输入的值
  And 提供重试而非成功提示

Scenario: 局部失败不抹掉可用数据
  Given 一个工作区的辅助资源请求失败且主资源成功
  When 页面展示结果
  Then 主资源及其可用操作仍可访问
  And 失败区域有准确说明及重试入口
  And 指标只反映可证明的数据范围
```
