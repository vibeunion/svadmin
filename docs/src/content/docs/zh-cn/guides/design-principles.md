---
title: 设计原则
description: 面向可信管理产品的七条 Stripe-first 原则
---

svadmin 把 Stripe 作为视觉权威，而不是品牌模板。中性表面、精确层级、克制
景深和紧凑控件服务于高频运营工作。以下七条原则把视觉方向转成可审查的
产品决策。

## 1. 默认清晰

每个页面只有一个主要任务、一个主操作，每个可见事实只有一个归属位置。

- 页标题、范围、当前状态和主操作使用可预测的顺序。
- 说明文案只补充约束、后果、范围或恢复路径。
- 同一个数字不能同时出现在标题、Notice、Badge、指标和表格中。
- 页头到主工作区最多保留一个高权重持久提示。

使用 `ContentPageShell`、`ContentPageHeader`、`SectionHeader` 和
`FeedbackNotice` 明确信息归属。

## 2. 缩短操作回路

高频后台操作应保留上下文，减少不必要的跳转。

- 本地操作后保留筛选、选择、排序和分页。
- 命令可通过键盘到达，控件紧凑且尺寸稳定。
- 数据变化时原位填充，加载和反馈不能挤走主操作。
- 使用 `PageToolbar` 和 `FilterToolbar` 组织高密度工作控件。

## 3. 契约一致

语义 Token、组件变体、状态命名、页面骨架和反馈生命周期在所有产品中
保持同一含义。

- 优先使用共享组件，再考虑页面局部变体。
- Layout preset 只能改变密度和构图，不能改变颜色语义、焦点、景深和反馈行为。
- 外部设计系统只提供行为或场景覆盖参考，不能成为第二套视觉权威。

## 4. 状态可信

加载、空、部分结果、错误、无权限、破坏性、可撤销和完成状态都要说明
影响范围与下一步。

| 情况 | 主反馈面 | 消失条件 |
| --- | --- | --- |
| 加载 | Skeleton 或 `DataState state="loading"` | 数据结束请求 |
| 没有匹配数据 | `DataState state="empty"` | 筛选或数据变化 |
| 可恢复错误 | 带重试的 `DataState state="error"` | 重试成功 |
| 权限边界 | `DataState state="forbidden"` 或 blocking notice | 权限或路由变化 |
| 普通成功 | Toast | 3 秒 |
| 工作流完成 | 新的页面或局部状态 | 跳转或重新开始 |

核心不变量：**one event -> one primary feedback surface**。

## 5. Stripe 式克制

让内容和层级承担界面表达。

- 使用中性画布和一个受控的交互强调色。
- 使用细边框、轻阴影、6px 控件和 8px 有界表面。
- Card 表示对象或有边界的工具；页面分区不能为了装饰而卡片化。
- 默认禁止渐变、Glow、玻璃感、负字距和 Card 套 Card。

## 6. 默认可访问

可访问性是组件默认值，不是最后修补。

- 所有操作支持键盘并保留可见焦点。
- 使用语义标题、Landmark、Label、Status role 和 Live region。
- 状态不能只依赖颜色表达。
- 保持可读对比度、稳定尺寸和至少 44px 的粗指针目标。
- 桌面与移动端都必须验证无裁切、重叠和横向滚动。

## 7. AI 可生成且可审计

生成界面在进入视觉润色前，必须声明主要工作流、信息归属、状态归属和
反馈消失条件。

当结果重复事实、装饰性嵌套卡片、发明第二套颜色、反馈没有生命周期，或
缺少桌面/移动端证据时，应直接拒绝。使用受信组件目录，并以完整的
[界面生成规范](/zh-cn/guides/interface-generation/)作为验收门。

## 审查顺序

依次审查：清晰、高效、一致、可信、克制、可访问、生成证据。即使页面
视觉精致，只要操作或状态归属不明确，仍然不通过。
