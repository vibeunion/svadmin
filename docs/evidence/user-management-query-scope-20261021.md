# 用户管理查询作用域与关联反馈

## 任务约定

- 日期：2026-10-21；parent：`ENTERPRISE_PRODUCT_SYSTEM.md` 的查询错误归属规则。
- source：用户要求“继续”；reason：接续用户管理查询作用域与局部恢复改造，
  完成尚未执行的单文件回归，并修复该范围内独立审查发现的不一致。
- 目标：用户管理按页面职责请求成员、角色、权限、账户、日志和设置；
  主列表可用时，关联查询失败显示局部提示并只重试失败关联。
- 非目标：不改身份认证、权限后端、成员写入或通用 CRUD 表；
  展示调整仅限依赖查询的计数、权限明细状态和账户页未加载的风险指标。
- Delegation Decision：medium、managed；主线程单写入者，一名只读 verifier。
- 写入范围：`UserManagementPage.svelte`、`pm-business-pages.test.ts`、
  本证据与产品规范中的对应规则；不改其他已有工作区改动，不提交或发布。

## 依赖规则

| 页面 | 当前资源 | 关联资源 |
| --- | --- | --- |
| 用户 | `users` | `roles`、`permissions`、`user_logs` |
| 角色 | `roles` | `users`、`permissions` |
| 权限 | `permissions` | `users`、`roles`、`user_logs` |
| 账户 | `user_accounts` | `users`、`roles`、`permissions` |
| 日志 | `user_logs` | `users`、`roles`、`permissions` |
| 设置 | `user_settings` | `users`、`roles`、`permissions`、`user_logs` |

查询错误不发送默认通知；主资源由 `WorkspaceQueryState` 承接，关联资源由
页面内的“重试关联资料”承接。失败不得折算成空列表或零指标。

成员、角色、权限在所有页面均为实际依赖，不添加恒真 `enabled` getter。
账户页不请求日志，因此不显示“风险事件”；成员、角色、权限三个指标仍保留。
折叠摘要里未启用的账户、日志、设置查询显示未知占位，不冒用缓存或零。
角色页的成员/权限加载或失败不能隐藏角色列表、搜索和编辑入口；
权限未成功读取时不显示“尚未分配权限”。关联恢复过程保留角色编辑节点。

## 验收

```gherkin
Given 用户目录读取成功但角色资料失败
When 页面显示用户列表
Then 用户记录仍可用，显示关联资料失败和重试入口

Given 关联角色资料失败
When 用户点击重试关联资料
Then 只重新请求角色资源，页面不触发成员写入

Given 六类用户管理页面的主资源读取失败
When 页面显示错误
Then 显示完整错误态，不显示空目录或默认通知

Given 角色列表读取成功而成员或权限正在加载或读取失败
When 用户查看角色及权限摘要
Then 角色列表和编辑入口保留，关联统计显示未知，重试只请求失败资源

Given 用户从日志关联失败的用户页切换到账户页再返回
When 当前页面资源变化
Then 账户页不请求日志也不显示风险指标，返回后恢复日志统计，禁用查询的摘要不显示零
```
