# Kanban 跨列移动持久化窄用例（2026-10-22）

## 范围

- 组件：`packages/ui/src/components/KanbanBoard.svelte`
- 单测：`packages/ui/src/components/kanban-board.test.svelte.ts`
- 本轮只验证前端移动契约：异步持久化回执、失败回滚与脱敏重试、`canMoveCard` fail-closed、重复提交互斥和 scope 隔离。
- 未实现后端排程、领域持久化服务或可替换排程引擎；未扩展到 Gantt/Scheduler。

## 红测

先补 3 条移动生命周期用例，并在既有权限矩阵用例中加入拖拽 fail-closed 断言：

1. 跨列移动必须等待异步回调，回调返回权威卡片回执时以回执提交，不提前提交乐观预览。
2. 服务端拒绝后回滚到源列，只显示本地化脱敏提示，不泄露原始错误；保留同一移动的重试入口，重试成功后提交。
3. 失败重试重复点击只产生一次新提交；切换 `scopeKey` 后清除失败提示与重试入口，旧作用域迟到拒绝不写入新作用域。
4. `canMoveCard` 拒绝或抛错时，卡片不可拖拽，拖放不触发 `oncardmove`。

修复前单文件：**5 failed / 20 passed（25）**。失败点为权威回执未消费、无重试入口、旧 scope 重试状态未清理，以及权限拒绝时卡片仍标记可拖拽。

## 修复

- `oncardmove` 可返回 `KanbanCard` 权威回执；仅在校验回执 id、目标列和卡片结构后替换乐观卡片，未返回回执时保持原有确认后提交行为。
- 失败移动记录 `failedMove`，提示区提供 `Retry`；重试复用同一卡片、目标列和目标索引，并受 `busy` 互斥保护。
- scope 变化时清空失败提示和重试状态；迟到结果仍通过原 scope 和 operation 引用丢弃。
- 拖拽可用性改为逐卡片调用 `canMoveCard`；拒绝、抛错、无目标列、加载/错误/忙碌状态均 fail-closed。
- 错误观察者抛错不会二次写入；界面不展示服务端原始错误。

## 第二轮：权威回执直接边界收口（2026-10-22）

### 范围与性质

- 仅修已有 `KanbanBoard` 权威回执入口的直接缺陷，不新增排程产品能力。
- 不代表用户已选择可替换引擎、Scheduler 或 Gantt；不构成领域交互、引擎替换或排程产品完成。
- 本轮新增边界均属本地可验证契约，不误列为“只能等后端”。真实后端回执字段、冲突版本、RBAC 和发布仍是外部验收。

### 新增直接边界（同一测试文件）

1. 错误 id、错误目标列、无效结构、`null` 回执均不得提交；乐观卡片回到源列，显示本地化通用错误，并可显式 `Retry` 同一移动。
2. 权威回执在提交后被回调持有方修改，不得改变已提交卡片；使用项目既有 `snapshotPlainData` 安全快照，而不是 `JSON.stringify` 克隆。
3. 异步成功或失败发生在组件卸载后，不得调用错误回调，也不得向已卸载组件交付迟到结果。

### 红测与修复

- 先补上述边界；无效回执和卸载后迟到结果在现有实现下已通过，未伪造失败。实际失败只有回执对象图别名：失败用例为嵌套 `tags` 被外部后续 `push` 修改，**1 failed / 31 passed（32）**。
- 修复：`KanbanBoard` 在提交前用 `snapshotPlainData` 复制回执，再校验 id、目标列和卡片结构；已提交卡片与回调持有方对象图完全分离。无效回执仍进入统一回滚与 `Retry` 路径。
- 新增仅用于绑定的 `kanban-board.test-host.svelte`，让测试可观察已提交卡片引用；不改变产品组件公开 API。
