## 当前证据

在 `scripts/fixtures/svar-grid` 执行：

```sh
node ../../../node_modules/@playwright/test/cli.js test \
  --config playwright.config.ts resource-loading.spec.ts \
  --output ../../../output/playwright/svar-grid-resource-loading-20261021/results \
  --reporter=line
```

结果：Chromium 10/10，退出 0，耗时 8.5 秒。真实 SVAR 引擎配合受控
HTTP 响应，复用现有 core 查询及权限上下文；Vite 服务执行后退出。

| 场景 | 已验证行为 |
| --- | --- |
| 首屏失败 | 一个内联错误；再失败仍保留错误；第三次读取恢复 |
| 滚动窗口 | 映射 core 分页，固定列同步，指定场景 gridcell 少于 300 |
| 窗口失败 | 再试相同窗口，恢复不回到首页；失败范围内单一错误 |
| 无限追加 | 追加后选择与 CSV 包含已加载的 50 条，不冒充全量 2000 条 |
| 追加失败 | 保留首页记录和已加载数量；恢复仅请求第二页 |
| 懒树读取 | 父级过滤正确；子记录导出权限拒绝时不下载 |
| 子节点失败 | 父记录仍可选择，失败仅在分支展示；恢复仅请求对应父级 |
| 撤权 | Grid 单元格移除，刷新入口禁用，观察期间无额外读取 |
| 旧作用域响应 | 测试释放旧响应后，当前页面没有出现旧记录 |
| 视口截图 | 1440x900、1920x1080、390x844 的资源窗口截图已生成 |

首屏、窗口、追加页、子节点失败/再次失败/恢复场景均显式检查
`notification-count` 和 `queued-toast-count` 为零，并确认页面不包含
`Fixture request failed` 原始诊断。
