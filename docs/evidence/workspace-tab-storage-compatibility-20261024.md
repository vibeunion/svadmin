# B3-09 工作区标签存储兼容与清理证据（2026-10-24）

## 目标

确认 `workspace-tab-state` 在当前 v1 存储契约下不会因用户作用域扩展而
错误读取旧数据，也不会把清理失败误报为已清理。

## 已核对行为

- 当前快照使用 `v1` 版本信封；版本不匹配、字段类型不合法、路径不匹配或
  JSON 损坏均按无快照处理，不做宽容迁移。
- 未登录 fallback 仅对当前租户的旧 `tenant + tab` 键做只读兼容；新写入仍
  使用带匿名用户命名空间的键。
- 显式 `userId` 不读取旧匿名键，且 envelope 中缺失或不匹配的 `userId` 会被
  拒绝，避免身份切换后复用旧草稿。
- 新键存在但损坏或带关闭信封时，不再回退旧键，避免绕过清理/损坏标记。
- `clear()` 会先建立内存和共享 tombstone；`removeItem()` 抛错、无效或回读
  仍存在时返回 `storage: 'failed'`，并尝试写入关闭信封。调用方不能把失败
  结果当作跨刷新删除保证。
- 同一 storage 对象上的其他 adapter 会观察共享关闭阻断；清理失败后只有
  经回读确认的新快照写入成功，才会解除阻断。

## 独立验证

```text
cd packages/ui
bunx vitest run --config ./vitest.config.ts \
  src/components/workspace-tab-state.test.svelte.ts
```

结果：**43/43，exit 0，7.34s**。

覆盖旧键只读兼容、显式身份隔离、版本/载荷拒绝、清理成功、清理失败、
跨 adapter 阻断和新快照接管等路径。

## 结论与边界

B3-09 的本地存储兼容与清理语义不再是当前代码阻塞，不需要为了“迁移”而
擅自读取未知旧版本或改变公共 API。当前 v1 选择 fail closed；若未来需要
迁移旧版本，必须另立版本映射、字段兼容和数据保留契约。

本证据不代表真实浏览器 storage 配额、跨浏览器标签页广播、真实身份/RBAC、
服务端业务草稿冲突、读屏实机、发布或部署验收。
