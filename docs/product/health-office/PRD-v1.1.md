# 智能辅助办公 PRD V1.1 — svadmin 页面实施补充

日期：2026-09-20。状态：页面与业务状态评审稿，非上线验收结论。

依据：本次对话《智能辅助办公系统 PRD V1.0》。本文件继承其完整一期需求；只说明当前代码覆盖与产品补充，不用演示替代一期交付。

## 1. 摘要与价值

为审核人员提供按风险排序的待办、结构化报告核对、预警处置和文档校对工作区；为复核、配置及审计人员提供不同权限的入口。目标是让每项提示有负责人、处理依据、版本和下一步，而非增加一个只能浏览的仪表盘。

当前产品形态：svadmin example 内 `/health_office` 工作区。复用 Svelte 5、svadmin 组件及语义 tokens；业务视图使用 `officeView`、`officeReport`、`officeAlert` 查询参数。独立懒加载，不接入库存 AI，也不改造其他业务。

## 2. 责任与岗位任务

| 岗位 | 任务与价值 | 当前假设 / 待确认 |
| --- | --- | --- |
| 审核员 | 优先接手高风险任务，核对来源，记录依据，完成审核 | 任务量、实际处理基线和组织分工待业务访谈 |
| 业务复核员 | 独立复核危急处置、误报及规则 | 谁具备医学规则批准资格待指定，不能由系统管理员身份替代 |
| 配置管理员 | 维护配置、移交待办后停用人员 | 不默认拥有报告读取或原件权限 |
| 审计员 | 查看操作轨迹及受控证据 | 保留期限、审计范围和导出策略待冻结 |
| 建设单位 / 安全 / 对接方 | 确认接口、数据处理和上线门槛 | 不编造具体联系人和已批准结论 |

未开展真实用户访谈。本稿的岗位和交互安排是基于 V1.0 的设计假设，不是已验证的用户研究发现。

## 3. 目标及度量

| 目标 | 实际测量方法 | 当前状态 |
| --- | --- | --- |
| 三步内到达并处理常规任务 | 从工作区起点到成功提交统计主要操作；必要填写、身份验证和复核不省略 | 主路径按三步设计，待真实用户可用性测试 |

## 5. 用户故事、确认条件与测试

故事按 Card / Conversation / Confirmation 编写，并以可独立验证的小任务为单位。所有设计引用为上一节的 UI / officeView；不是不存在的 Figma 链接。

### US-01 授权范围内查找待办（UI-01、02、06）

作为审核员，我需要在自己的范围内找到最高风险任务，以免无效切换或看到其他部门资料。

验收：列表、预警和统计同范围；直接使用未知或越权 ID 不显示对象；配置管理员不自动获得报告权限；空筛选与无权限分别展示；分页不扩大授权范围。自动化：`授权范围与最小权限` 测试组。

### US-02 记录文件导入失败（UI-03）

作为审核员，我需要知道每个文件为什么没有进入报告流程，以便纠正而不重复提交整批。

验收：逐文件处理；空文件/不支持类型/超过限制有原因；有效文件仍显示等待真实服务；取消不删除既有报告；不读取或上传真实内容。自动化：混合导入、批量边界与取消测试。真实病毒扫描不是本地扩展名测试的验收内容。

### US-03 核对和修正派生数据（UI-04、05）

作为审核员，我需要记录修改依据并保留原始结果，以便复核者能追溯。

验收：修改不覆盖原始值；保存要求原因；缺失单位保持无法判定；身份冲突不能一键通过；变更使检查过期并重开受影响预警；旧版本提交失败且不改变数据。自动化：报告版本、原值保护、身份冲突和并发测试。

### US-04 独立复核危急处置（UI-06、07、11）

作为审核员和复核员，我们需要明确区分已读、接手、处理和关闭，避免通知记录冒充实际处理。

验收：消息已读幂等但不确认预警；领取进入处理中；误报和交接必须有证据；一级预警必须独立复核；有复核权限也不能自审自己的处置；处理说明与前后状态保留。自动化：`预警状态与复核门禁` 测试组。

2026-09-21 补充：独立复核员可填写原因退回原负责人；状态回到处理中，不关闭预警、不删除上次证据；再次提交须使用新版本。退回同样校验权限、部门、版本和禁止自审。对应测试“独立复核可有依据地退回并由原负责人重新提交”和“退回同样要求独立权限、正确状态和部门范围”。宿主侧栏离开保护、仅修改处置类型时的未保存提示及取消保值另需浏览器验证。

### US-05 校对只修改审核稿（UI-08）

作为审核员，我需要查看建议的上下文并逐项决定是否采纳，以免误改原报告。

验收：原始文本不变；文本版本和原文区间同时匹配；手动编辑使旧建议失效；忽略仅影响本条；白名单申请不自动启用；离开有未保存修改时提示。自动化：原文保护、区间/版本失效、忽略/白名单、改稿重开测试；离开提示需浏览器用例。

### US-06 在服务失败时人工接管（UI-05、08）

作为授权审核员，我需要留下人工检查记录，不能把服务故障当作正常。

验收：检查状态明确失败；先完成人员核对；不得跳过未处理建议；人工结果标为人工而非自动；完成报告前所有门禁满足。自动化：人工接管及端到端业务状态成功路径。

### US-07 规则审批与任务移交（UI-10、12）

作为配置管理员，我需要让独立业务人员复核规则，并在停用人员前处理其待办。

验收：编辑者不能自审；未复核不能演示发布；演示发布不改写历史报告；有待办时要求转移确认；跨部门任务阻断无权限停用；停用后业务命令拒绝执行。自动化：规则审批、停用、跨部门与历史保留测试。

### US-08 可解释统计与追溯（UI-09、13）

作为业务管理与审计人员，我需要分清可判定观测、排除项和实际变更，以免错误理解报表。

验收：服务失败/缺失结果不进入有效分母；无分母显示“—”；支持钻取；日志只读；一般运行日志不保存完整正文，业务快照单独保留。自动化：分母、正文隔离、变更快照测试。

## 6. 测试场景与观测结果

代码：`example/src/office/domain.test.ts`。当前 28 项纯业务状态测试覆盖上述故事的主要成功和失败路径。

| 场景 | 初始状态 / 角色 | 操作与可观察结果 |
| --- | --- | --- |
| 危急处置 | worker，A001 待确认 | 标消息已读仍待确认 → 领取进入处理中 → 提交进入待复核 → 换 reviewer 通过后关闭 |
| 自审拒绝 | reviewer 自己领取并提交 | 同一 reviewer 关闭被拒绝，状态和证据不变 |
| 文本版本 | R001 初始建议和工作稿 V1 | 采纳后原文不变、工作稿 V2、其他旧建议失效；旧页面提交冲突 |
| 人工接管 | R002 服务失败，质量已核对 | 分别填写依据完成异常/校对人工检查；仍需关闭预警才能完成报告 |
| 停用移交 | admin，worker 有待办 | 未勾选移交则失败；确认移交后进入部门队列，worker 后续操作失败 |
| 越权与空态 | admin 或无效报告 ID | 不显示报告，不泄露数量；worker 搜索不存在关键词显示空结果 |

代码已提供测试不等于测试已经运行。当前执行证据见随交付的验证日志；全量 Svelte 类型、生产构建和浏览器回归须以实际 CI 结果为准。

### 暂不构成一期阻断的担忧

没有疾病预测模型不会阻止一期报告审核业务的交互验证；二期能力关闭符合原始边界。无需为了展示页面引入新的 UI 框架或复制第三方付费素材。这不豁免一期的安全、权限或实际接入要求。

### 尚未验证的重要假设

医保接口是否实际提供完整体检报告；不同机构的参考范围如何批准；谁承担非工作时段确认；报表的统计时区和去重标准；原件、审核稿、日志与备份的保留期限。由对应责任方在接入清单冻结前确认，不编造默认临床阈值。

## 8. 分阶段交付与技术边界

本轮交付：svadmin 页面、纯业务状态层、合成数据、自动化状态测试、PM 技能适配和产品补充。仅用于需求评审与开发验证。

下一阶段：服务端认证/范围权限、报告和版本持久化、原件对象存储、受控上传与导出、任务队列及审计。HTTP 命令携带 `expectedRevision`、`idempotencyKey`、`requestId`；服务端重新鉴权，不信任前端 actor。状态错误区分 403、409、422、503。算法实现仍排除。

联调阶段：OCR、预警、校对和通知能力适配；签名、超时、重复/过期回调、重试及人工兜底。HL7/FHIR 版本和资源子集按对接方冻结，不承诺任意标准或版式。

一期上线：补齐上表尚未完成的一期功能，执行真实性能、兼容、备份恢复及安全验收；不能用 28 项状态测试或页面数量宣布一期全部完成。

任务执行记录：单一代码写入者；当前运行环境无可调度的独立代码复核执行器，不能声称已完成独立工程审查。业务风险通过隔离合成演示和明确上线阻断处理；合并/发布/部署需另行证据和授权。
