# Surface phase 2: incremental renderer and style edit preview

Continuation of phase 1, explicitly requested on 2026-09-19. The existing
`surface/v1`, DataProvider and read-only policy boundaries remain in place.
This slice implements actual renderer reconciliation and a user-confirmed edit
preview; it does not claim a complete OpenUI language, orders CRUD or repository
Tailwind migration.

## Implemented

`SurfaceRenderer` now reconciles sources by stable ID, normalized query,
projection policy and provider identity. Title/layout/widget-order-only changes
reuse in-flight or ready data. Changed sources reload individually, removed
sources are invalidated, and explicit `refresh()` still forces a reload.
Destruction and source/scope replacement invalidate outstanding responses. An
invalidated asynchronous authorization cannot subsequently launch a query.
This discards stale responses; it does not claim transport-level cancellation.

The renderer updates individual source-state keys and keeps Svelte widget keys.
Unchanged widget IDs and component types retain local input state when visual
edits are applied. Changing a component type or removing it can intentionally
remount it. A changed trusted `scopeKey` clears data and remounts widgets.

**The host must change scopeKey and discard pending AI proposals when switching
user, tenant or authorization session.** This is not a model-provided field.
Frontend checks and revision comparison do not replace backend authorization,
server-side compare-and-swap, or a tenant-bound persisted surface identity.

`SurfaceEditPreview` accepts a controlled revision and an untrusted
`surface-edit/v1` proposal. During streaming it leaves the current surface
unchanged and disables preview/apply. After full validation, the user can preview,
return to the current surface, or explicitly apply. Apply revalidates with the
latest revision/catalog/policy before calling the trusted host callback. It does
not save, call a model, grant permissions or execute a business mutation itself.
The host updates `revision` only after successful application/persistence and
clears the old proposal. Missing handlers and failed/obsolete proposals cannot
be applied. Pending callbacks disable duplicate user submissions.

## Static style integration

Static Surface styles are a **build-time concern of @svadmin/surface**. The new edit-preview
UI is authored with scoped tokens and two recipes. All two density and two button
variants are emitted ahead of time. Recipe class mappings are generated by the local
not guessed by the runtime. Tokens reuse the existing complete-color CSS variables
with fallbacks. A postprocessing gate removes unused global base-variable
initializers and rejects unscoped selectors, compiler directives and oversized CSS.

The generated stylesheet and class mapping are checked in and rebuilt during
package builds. The component imports plain compiled CSS; consumers do not need
compiler-free build and do not require Tailwind plugins or dependency-source scanning. `@svadmin/surface/editor.css`
is also exported for explicit CSS collection. The DOM-free root still imports no
Svelte components or styles. Legacy UI components and example styles still use
their existing styling implementation; this is not repository-wide Tailwind
removal.

```svelte
<script lang="ts">
  import { createSurfaceRevision, type SurfaceRevision } from '@svadmin/surface';
  import { SurfaceEditPreview, defaultSurfaceCatalog } from '@svadmin/surface/svelte';
  // initialSpec and policy come from trusted host setup; model text is untrusted.
  let { initialSpec, policy, dataProvider, sessionKey } = $props();
  const result = createSurfaceRevision(initialSpec, defaultSurfaceCatalog, policy);
  if (!result.ok) throw new Error('Invalid initial surface');
  let revision = $state.raw<SurfaceRevision>(result.value);
  let proposal = $state<unknown>();
  let streaming = $state(false);
  function apply(next: SurfaceRevision) {
    // For durable state: authorize and atomically compare revisions server-side
    // before updating the controlled revision here.
    revision = next;
    proposal = undefined;
  }
</script>
<SurfaceEditPreview {revision} {proposal} {streaming} {policy} {dataProvider}
  scopeKey={sessionKey} onApply={apply} />
```

## Validation gates

Run the package component/protocol suites, strict typecheck, `styles:check`, full
repository CI and package-consumer checks. `styles:check` verifies finite variant
coverage, deterministic output and absence of global selectors. Browser evidence
uses real built package components in Vite with only the Svelte plugin (no CSS
or Tailwind plugin), including unsaved input retention, explicit apply, streaming,
invalid proposals, theme overrides, keyboard focus and narrow viewports.
Test definitions are not proof of passing; exact-head workflow results are the
source of validation status.

## Next slices
