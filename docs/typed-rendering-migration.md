# 业务页面原生类型化渲染迁移

本轮承接 PR #432 的适配层，并按用户要求将业务调用点一次性迁移。组件主线保持 Svelte 5，不增加 TSX、React 或样式依赖；不合并其他样式、SVAR、Surface 分支，也不发布或部署。

## 覆盖清单

`example/test/business-page-inventory.json` 列出全部 **22 个页面入口**，测试枚举实际目录来检查遗漏。`example/src/resource-rendering.ts` 明确列出全部 **52 个资源**，每一项通过轻量 `createResourceRendering` 绑定既有 `demoContracts`，保留字面量键的类型推导。

| 范围 | 实施方式 |
| --- | --- |
| 仪表盘、AI、日历、CRM、房地产、待办、用户管理 | 查询结果经过各自 `demoRenderers.<resource>.records`，再供原生模板渲染 |
| 库存、运营、订单、通知、商店、项目、账单、安全、邀请等动态工作台 | 按实际资源分支校验数据；数值、筛选、聚合字段受具体记录类型约束，不再用宽泛 Row 或数值强转 |
| 收件箱、草稿、已发送、归档、稍后处理、垃圾邮件、废件箱 | 七种资源分别校验，再构造共同展示模型 |
| 既有九个轻量页面入口及通用资源页 | 传递同一资源的 rendering，通用 ResourceOperationsPage 向所有16个原生表格分支继续传递 |
| 快速编辑和详情抽屉，以及 CreatePage/EditPage/ListPage/ShowInferencer | 将同一 rendering 继续传递到实际表单/详情/表格，不在抽屉或包装组件处丢失绑定 |
| 所有资源 create/edit/clone/show 路由 | 使用 BusinessAutoForm / BusinessShowPage，不再退回未接入的默认页面 |
| CaseWorkspacePage | 本来使用本地强类型状态；补上实际阶段枚举校验，移除阶段类型断言 |
| DesignPrinciplesPage | 已是静态强类型原生组件展示，无远程资源记录需要迁移；保留并纳入22页清单与浏览器导航检查 |
| Lite 示例列表/新建/编辑/详情四个服务端页面 | 已使用 SvelteKit PageProps 和服务端校验数据；保持 SSR 边界，不引入浏览器 UI 包。既有 Lite SSR 门禁继续适用 |

框架的通用组件仍允许外部使用者不传 rendering，以兼容动态资源。只有明确动态的路由分发接口使用 ResourceRendering 的擦除类型；具体业务字段、聚合、图表和列表保留精确资源类型。注册表并不宣称任意 runtime 字符串可以静态推导为某一确定资源。

## 保持的行为与防护

原生表格仍保留行内编辑、批量操作、筛选、排序、展开行、视图和导出。原生表单保留错误提示的 aria 关联、首错焦点、密度、禁用、导航确认与异步提交所有权。未使用全局默认渲染 snippet 覆盖这些行为。

相同名称但不同实例的契约不能混用；非法数组和记录不会进入强类型视图；输入过程中的草稿可以暂时无效，但提交仍须通过完整业务契约。每次 records 校验返回独立快照，不缓存可变数据的对象身份；额外校验有开销，不宣称零成本。

## 验证

- example 测试枚举52个资源并校验所有种子记录，检查本地化资源注册的契约身份；22页清单与实际 Svelte AST 接入点对照。
- 六项业务类型反例检查字段拼写、数值字段、筛选值以及跨资源字段混用。
- 既有 AutoTable 交互与 AutoForm 无障碍测试使用已接入的真实组件；保留完整表单契约/会话测试。
- `Typed renderer contracts / business-pages` 构建生产应用，验证所有资源的列表、新建、现有记录编辑、克隆、详情导航，并测试真实行内编辑、快速编辑持久化以及1440x900和1920x1080截图。

浏览器结果以当前提交的 Actions 产物为准；配置了测试不等于测试已经通过。截图用于真实页面证据，不自动等同于逐像素视觉兼容性证明。发布和合并仍须完整仓库CI与审查通过。

首屏预算不放宽：仪表盘仅在实际进入仪表盘时通过原生异步组件加载，登录页不再提前下载仪表盘模板；加载与错误状态仍提供无障碍反馈。
