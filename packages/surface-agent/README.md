# @svadmin/surface-agent

Optional human-approval workflow for `@svadmin/surface`. It turns one constrained Agent component into a visible, expiring Patch proposal; it never gives an Agent direct access to resource data, document storage, actions, scope selection, or writes.

## Install

```bash
bun add @svadmin/surface-agent @svadmin/surface @svadmin/core zod
```

Add `svelte` when using the review component. `@svadmin/surface` rendering applications also need the Core/UI peers documented by that package.

## Create a workflow

```ts
import {
  createSurfaceAgentWorkflow,
  requestSurfaceProposalFromAgent,
} from '@svadmin/surface-agent';

const workflow = createSurfaceAgentWorkflow({
  dependencies: {
    store,
    catalog,
    policy,
    authorize: async ({ scopeId, surfaceId, actorId, action }) =>
      permissions.canChangeSurface({ scopeId, surfaceId, actorId, action }),
  },
  scopeId: 'tenant:acme',
  surfaceId: 'inventory',
});

const proposed = await requestSurfaceProposalFromAgent({
  provider: agentProvider,
  messages,
  workflow,
});

if (proposed.ok) {
  // Show proposed.review.before and proposed.review.after to a human.
  const applied = await workflow.approve({
    proposalId: proposed.review.proposalId,
    actorId: currentUser.id,
    operationId: crypto.randomUUID(),
  });
}
```

The `AgentProvider` stream must contain exactly one component named `svadmin.surface.patch-proposal/v1`. Its props have this shape:

```ts
interface SurfaceProposalInput {
  proposalVersion: 'surface-proposal/v1';
  surfaceId: string;
  baseRevision: number;
  summary: string;
  operations: SurfacePatchOperation[];
}
```

Tool calls, approval requests, tool results, multiple components, unknown components, and missing proposals are rejected. Agent input cannot set `scopeId`, actor identity, proposal ID, catalog, policy, provider, or credentials.

## Review UI

```svelte
<script lang="ts">
  import { SurfaceProposalReview } from '@svadmin/surface-agent/svelte';

  async function approve() {
    const result = await workflow.approve({
      proposalId: review.proposalId,
      actorId: currentUser.id,
      operationId: crypto.randomUUID(),
    });
  }
</script>

<SurfaceProposalReview
  {review}
  onApprove={approve}
  onReject={() => workflow.reject({
    proposalId: review.proposalId,
    actorId: currentUser.id,
  })}
/>
```

The component displays the summary, digest, expiry, changed paths, and complete before/after JSON. It does not approve automatically.

## Approval guarantees

- Proposal IDs are generated by the host; the default uses `crypto.randomUUID()`.
- A SHA-256 digest binds scope, surface, base revision, catalog version, summary, and operations.
- The bounded Patch is previewed and fully validated before entering `pending`.
- Proposals expire, are single-use, and cannot be replayed after a decision.
- Approval authorizes `approve`, then re-reads and revalidates the current document, authorizes the actual `write`, and commits with revision compare-and-swap.
- Rejection, expiry, stale revision, invalid Agent output, failed authorization, and replay perform zero document writes.
- Applied revision provenance records the host proposal ID, digest, Agent origin, reviewing actor, and operation ID.

Pending proposals are stored in memory by this first workflow adapter. Production hosts that require restart-safe queues or durable approval audit should persist proposal state on a trusted server. Document revisions themselves use the application-supplied `SurfaceStore` from `@svadmin/surface`.

Browser approval is a workflow gate, not a backend security boundary. Durable stores and data APIs must independently authenticate and authorize requests; never trust browser-provided actor, scope, policy, revision, or approval state.

## Compatibility

The supported peer ranges and minimum consumer combination are recorded in `compatibility.json`. During a workspace release, Release Please rewrites the `workspace:*` Surface peer to the released Surface version before publishing. Packed-consumer checks validate the Node ESM entry, Svelte entry, and release-prepared peer manifest.
